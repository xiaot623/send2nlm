# 基于资源的生成流程设计

> **版本**: v0.7-draft
> **状态**: 方案阶段
> **目标**: 支持基于单个/选中资源生成音频、幻灯片、视频，替代当前"整个 Notebook"的粗放模式

---

## 1. 当前流程 vs 目标流程

### 当前流程（v0.6）

```
用户 → 选笔记本 → 确认发送（选任务）→ 一键执行全链路
                                          ├─ URL → PDF
                                          ├─ 上传到笔记本
                                          ├─ 在整个笔记本上生成
                                          ├─ 轮询 → 下载 → 投递
                                          └─ 完成

问题：生成始终基于笔记本全部资源，无法限定范围。
```

### 目标流程（v0.7）

```
用户 → 选笔记本 → 自动上传资源 → 资源列表（可选）→ 选任务 + 选资源 → 生成
                                                                      ├─ 基于指定资源生成
                                                                      ├─ 轮询 → 下载 → 投递
                                                                      └─ 完成
```

关键变化：**上传与生成解耦**。上传在选笔记本时立即触发；上传完成后展示资源列表，用户可精确选择基于哪些资源生成。

## 3. 后端 API 设计（语义层面）

### 3.1 上传资源：`POST /notebooks/{id}/upload`

**职责**：接收一个 URL，将对应页面转为 PDF 并上传到指定笔记本，完成后返回该笔记本下所有资源的列表。

**输入**：
- 笔记本 ID
- 待上传的网页 URL

**Daemon 执行**：
1. Producer 链：URL → PDF（包含飞书、通用网页等适配器）
2. 上传 PDF 到 NotebookLM
3. 调用 `notebooklm source list` 拉取该笔记本的完整资源列表
4. 返回：新上传的资源信息 + 全量资源列表

**输出语义**：
- 成功：返回刚上传的资源 ID + 完整资源列表（每个资源含 id、名称、类型、状态）
- 失败：返回错误原因，前端展示重试入口

### 3.2 获取资源列表：`GET /notebooks/{id}/sources`

**职责**：获取指定笔记本下所有已上传的资源列表。

**使用场景**：
- 用户返回 Page 1 后再次进入同一个笔记本（无需重新上传）
- 手动刷新资源列表
- 未来：用户在 Page 3 点击刷新按钮

### 3.3 触发生成：`POST /jobs`

**职责**：基于指定笔记本的指定资源，触发生成任务。

**输入**（扩展后）：
```
{
  notebook_id,      // 目标笔记本
  source_ids,       // 本次生成所基于的资源 ID 列表（必填）
  tasks,            // 要生成的内容类型
  url               // 原始网页 URL（用于展示和记录，元数据）
}
```

**Daemon 执行**：
1. 对每个 task 调用 `notebooklm generate <type> -s <source_id> ...`，限定生成范围
2. 先等待 10 分钟，再轮询所有任务直到完成（每 1min，总上限 60min；超过上限时先做最后一次状态查询，仍未完成才失败；daemon 重启后按 SQLite 中的 polling_started_at 继续）
3. 下载产物
4. Receiver 投递

**与旧版的关键区别**：
- 旧版：不传 `source_ids` → 整个 Notebook 生成
- 新版：必须传 `source_ids` → 仅基于选中的资源生成
- 不再包含 PRODUCING 和 UPLOADING 阶段（这些已在 `/upload` 中完成）

## 4. 关键设计决策

### 4.1 为什么上传与生成要解耦？

| 维度 | 紧耦合（当前） | 解耦（目标） |
|------|---------------|-------------|
| 资源可见性 | 上传后不可见中间状态 | 上传后立即看到资源列表 |
| 范围控制 | 无法选择，全量生成 | 精确选择基于哪些资源生成 |
| 重试能力 | 失败需从头开始 | 上传成功后，生成失败可重试 |
| 扩展性 | 难以支持"不传 URL，只选现有资源生成" | 自然支持：跳过上传，直接选资源生成 |

### 4.2 刚上传的资源默认选中

- 绿色 `[新]` 标记，明确标识
- 默认勾选，符合"基于这个页面生成"的直觉
- 用户可以取消勾选（比如传错了、不想基于它生成）

### 4.3 上传失败的处理

- Page 2 spinner 切换为错误提示 + 重试按钮
- 用户可点返回按钮回到 Page 1，换一个笔记本
- 不阻塞后续流程

### 4.4 未来：纯"选择资源生成"模式

解耦后的架构自然支持不传 URL、仅选现有资源来触发生成。这是第 3 页中取消勾选新资源、只勾选旧资源的自然延伸。

---

## 5. 扩展路线图

| 阶段 | 内容 |
|------|------|
| **Phase 1（当前）** | 实现上传与生成解耦。选择笔记本 → 上传 → 资源列表 → 选资源生成 |
| **Phase 2** | 资源列表支持搜索/过滤、显示资源状态（处理中/就绪/失败） |
| **Phase 3** | 不传 URL 模式：直接选已有资源触发生成（不上传新页面） |
| **Phase 4** | 批量操作：一次选中多个笔记本的资源进行生成 |
